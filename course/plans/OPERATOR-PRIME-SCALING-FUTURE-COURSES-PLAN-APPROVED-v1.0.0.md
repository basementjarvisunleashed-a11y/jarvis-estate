## Scaling principle
Scale by versioning, not by overwriting. A new course, module, lab, or hardware piece starts as its own versioned draft, with its own gate, its own evidence standard, and its own place in the index. It is taught only after HgX locks it expressly. Locked files stay locked. Draft files stay draft. Nothing is deleted.

## Pipeline, in order (ideas only, not locked)
1. Finish the locked core first: M0–M14, L1–L20, H1–H20, Project 25, 21 checkpoints, assessment, capstone L20, all with filed evidence.
2. Expansion locked for 1.0 (Addendum 2): H21–H30, each with an openness check at purchase and a hardware gate; L21–L50, each with a lab gate; L50 final year capstone, with its three-week structure.
3. Add future modules only on HgX's word, each as its own draft: a module draft names its labs, its hardware, its evidence standard, and its place in the sequence before it is taught.
4. Add future courses only on HgX's word, each as its own course tree: its own syllabus draft, its own structure draft, its own labs draft, its own handbook, its own schedule draft, its own logs draft, its own Dean feed. A future course never borrows a locked OPERATOR PRIME lab as its own without a new version naming the borrowing.
5. Scale the professor feed with the course count: one Dean feed per course, daily / weekly / monthly, each feed versioned separately, each professor room briefed separately on HgX's word.

## Distribution, every new version, every time (Dean's standing rule, 2026-11-04)
Every new or revised course file, and every future course file, is:
- Versioned (new version, never an overwrite of a locked file, never a deletion).
- Indexed (course README / index updated, with status locked / draft / history stated plainly).
- Sent to the Publishing House, for GitHub and the course website, on HgX's order, with commits and live addresses reported back.
- Filed in the Dropbox education dossier, in a versioned subfolder, never overwriting an existing file (new version suffix if a file of that name already exists).
- Staged in a OneDrive-ready package, in the same versioned structure, for upload once OneDrive access is connected (see the distribution note in the Dean's delivery: OneDrive has no connector in Muse at this time, so direct OneDrive upload is not yet available here — the package is staged, not claimed as uploaded).
- Never sent to a public surface with sealed substance, personal data, prompt text, or later-version substance. Sealed lab material stays sealed, and is published only on HgX's explicit command for that specific item, if ever.

## What scaling never does
Never invents a year, a start date, a clock time, a holiday date, a venue name, a course code, or an accreditation. Never claims a draft as locked, a planned stack as built, or a draft hardware piece as in hand. Never deletes a history file to make room for a new file.
