## Gate rule, every piece, no exceptions
No lab starts until the hardware it requires has passed its own gate. A gate is: box photo, cable check, USB recognised on Kali, safe self-test passed, HgX says go (or professor confirms go under the Dean's feed, where HgX has delegated that check). Record tool, version, command, output, measurement, and error for the gate itself.

## Per-piece checklist (copy per piece, one sheet per piece per cohort)
- Piece and code (H1–H30), and whether it is locked (H1–H20) or draft (H21–H30).
- Open-hardware status: open schematics / open hardware documentation published by the vendor, or software-only / partial openness stated plainly. If a piece turns out closed, it drops to reference only — it does not become course hardware by assertion.
- Box photo filed (file path), cable filed, USB recognised on Kali (output filed), safe self-test on own target only (output filed), measurement against ground truth where applicable.
- Failure mode: what failed, method, error, workaround or replacement gate, resubmission filed. A failed gate stays failed until it passes.
- Deletion and storage: own targets secured at close, templates/recordings deleted where required, deletion log filed.
