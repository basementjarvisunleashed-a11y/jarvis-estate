## What Project 25 proves
The entire suite, proved by evidence, not by presence alone. 21 family checkpoints: 15 core + 6 specialty (GPU, Bluetooth, RFID, SDR, VoIP, Labs). Each checkpoint requires: tool present, safe self-test on an own target, evidence saved.

## Tiers
- Tier 1: presence + self-test for all 21 checkpoints.
- Tier 2: lab-target functional tests for the core 15 checkpoints.
A checkpoint is complete only when its tier evidence is filed. A checkpoint with a tool installed but no self-test is not complete. A checkpoint with a self-test but no filed evidence is not complete.

## Per-checkpoint log (copy per checkpoint, 21 copies per cohort)
- Family and checkpoint code, tool name, version recorded, command recorded, output filed, measurement filed, error filed.
- Self-test: own target only, safe test only, result filed, before-and-after where a hardening change applies.
- Gate status: passed / failed (with method, error, resubmission) / not yet run. Never passed by assertion.
- File paths for every capture and log, in the evidence pack standard.

## Prove-out order (template, no dates locked)
Prove in family order, one family at a time, with a gate per family, before moving to the next family. If a family fails, log it, fix it, re-test it, and file the re-test as a new version. Do not skip a failed family to keep a schedule.

## Planned vs built, stated plainly in every workbook copy
Built, per the course brief and files: Kali Linux everything on the Acer internal drive, REA rea-agents@6.7.0 ready for local app analysis. Planned, not built: Ollama check, 4B VRAM fast low-end model, 27B RAM slow high-end model, switching logic, remaining software stacks in efficient order, Kali tools mapping into REA, Project 25 prove-out itself. Present planned as planned, built as built, in every copy. Never present a planned checkpoint as proved.
