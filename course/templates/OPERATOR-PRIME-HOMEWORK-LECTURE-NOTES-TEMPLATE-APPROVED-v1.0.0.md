## Lecture notes template (per module, GenOffice written + VoiceStudio narrated)
- Module code and title, learning objectives for the module, headline first (layers rule: headline, then depth).
- Key concepts, in order, each tracing to a filed lab log or capture. No lecture claim without a log entry.
- Lecture generated from live lab evidence locally: slides, video, visuals, narration, every claim traces to live test output.
- Professional register throughout. No sports or entertainment references in course materials.
- Graphify section: flaw, device, method, defence linked, local only, part of the evidence pack.
- Image section: teaching visuals only (ComfyUI / HyperFrames, local), not evidence by themselves.
- Cartographer section: LiDAR, drone, satellite, mesh, site maps, with ground truth — not a new software stack.

## Homework template (per week, per module)
- Reading: lecture notes for the module, plus local tool documentation for the week's tools.
- Teardown write-up: one own lab target, REA, version + hash, strings first, code second, flags found, confidence scored BEFORE the write-up, one ledger row per finding.
- Evidence log: complete the week's log, tool, version, command, output, measurement, error, file path, for every lab step.
- Hardening answer: one concrete defence change for the teardown finding, with a re-test plan. Resubmit until pass.
- Graphify block: add the week's flaw, device, method, and defence to the local knowledge graph.
- Close: homework pack filed, resubmissions filed, next lab day's reading noted. No new teardown on a buffer homework day — catch-up only.
- Never: a real target, a non-owned target, a reproduced attack prompt, a personal datum.

## Resubmission rule
Homework is resubmitted until it passes. A resubmission files the new work as a new version, naming what it corrects. Nothing is deleted or overwritten.
