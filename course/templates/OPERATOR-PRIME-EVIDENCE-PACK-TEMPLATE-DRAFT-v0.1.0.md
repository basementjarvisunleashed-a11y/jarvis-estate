## Folder standard (one folder per laboratory, subfolders as below)
- `00-checklist/` — lab checklist, gate status, hardware gates used.
- `01-tool-log/` — tool, version, command, output, measurement, error, for every step, in order.
- `02-captures/` — scans, captures, traces, maps, photographs, with file paths and ground truth tables where applicable.
- `03-analysis/` — findings, confidence scored BEFORE the write-up, one ledger row per finding, hardening change, before-and-after test results.
- `04-report/` — written report draft (GenOffice), narrated summary draft (VoiceStudio), defence brief draft.
- `05-logs/` — daily log, deletion log where required, inspection notes, corrections filed.
- `06-graph/` — Graphify update: flaw, device, method, defence linked, local only, part of the evidence pack.

## Filing rules
- Evidence is filed the same day it is made. A day does not close with an unfiled log. A lab does not close with an unfiled evidence pack.
- Every file name carries lab code, date-order, and content in plain words (for example, `L05-bus-capture-before-harden`). No file name carries a personal name, a Wi-Fi name, a serial, a password, or a credential.
- Corrections are filed as new files naming what they correct. Nothing is deleted or overwritten. A corrected file does not erase the original.
- Visuals (ComfyUI / HyperFrames) are teaching visuals only, not evidence by themselves. Every visual claim traces to a filed capture or log.
- Lecture claims trace to live test output only. No lecture claim without a log entry.

## Gate checklist, per pack (copy and tick, do not invent a tick)
- [ ] Lab goal and module(s) stated.
- [ ] Hardware gates passed for every piece used.
- [ ] Tool log complete, in order, with versions.
- [ ] Measurements quantified, error against ground truth stated where applicable.
- [ ] Hardening change filed, re-test filed, before-and-after compared.
- [ ] Deletion log filed where required (templates, recordings).
- [ ] Inspection note received, correction filed.
- [ ] Gate status: passed / failed (with method, error, resubmission) / not yet run. Never passed by assertion.

## What never goes in a pack
No personal data, no real names, no Wi-Fi names, no home addresses, no serials, no passwords, no credentials, no live location, no family details, no financial details. No attack prompt text. No later-version, sealed, or alpha substance. Defence commentary only.
