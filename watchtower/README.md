# Watchtower

Honest uptime monitoring for a personal AI estate. One script, one manifest,
one status page.

## The idea

Most status pages answer "is it up?" Watchtower answers the more useful
question: *what is each service doing, and is that what the operator asked
for?* A service the operator deliberately paused reads as **paused** — a
decision, not an outage. That distinction is the whole point.

## Run it

```bash
python3 watchtower.py --services services.yaml --out .
```

Stdlib only — no dependencies. Optional `--extra extra.json` merges
externally-resolved states (e.g. cron states gathered by your scheduler),
overriding script-resolved checks by service name:

```json
{"services": [{"name": "morning-briefing", "state": "paused",
               "note": "paused by operator; resumes on their word"}]}
```

Output: `status.json` (machine-readable) and `STATUS.md` (human-readable).
Exit code is 0 unless something is `degraded`.

## Check kinds

| Kind   | What it does |
|--------|--------------|
| `http` | GET the target; 2xx–3xx is operational. A 403 (bot protection) is reported as `unknown`, not down. |
| `file` | Present on disk or not. |
| `cron` | Needs an external resolver — pass its state via `--extra`. |

## States

- 🟢 **operational** — doing its job.
- ⏸️ **paused** — the operator paused it deliberately.
- 🔴 **degraded** — failing; needs attention.
- ⚪ **unknown** — could not verify from here.
